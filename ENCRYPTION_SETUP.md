# 🔐 Настройка шифрования персональных данных

## Быстрый старт (3 шага)

### Шаг 1: Сгенерируйте ключи

```bash
python3 generate_keys.py
```

Вы получите два ключа:
- **SECRET_KEY** - основной ключ безопасности
- **ENCRYPTION_KEY** - ключ для шифрования данных (опционально)

### Шаг 2: Создайте файл .env

Скопируйте `.env.example` в `.env`:

```bash
cp .env.example .env
```

### Шаг 3: Добавьте ключи в .env

Выберите один из вариантов:

#### ✅ ВАРИАНТ 1 (Рекомендуется для продакшена)

Используйте **ОБА ключа** для максимальной безопасности:

```env
SECRET_KEY=ваш-сгенерированный-secret-key
ENCRYPTION_KEY=ваш-сгенерированный-encryption-key
```

**Преимущества:**
- Максимальная безопасность
- Разделение ключей для разных целей
- Можно менять ENCRYPTION_KEY без влияния на JWT

#### ✅ ВАРИАНТ 2 (Упрощенный, подходит для большинства случаев)

Используйте **ТОЛЬКО SECRET_KEY**:

```env
SECRET_KEY=ваш-сгенерированный-secret-key
# ENCRYPTION_KEY оставьте пустым или закомментируйте
```

**Преимущества:**
- Проще в настройке
- Один ключ для управления
- Ключ шифрования автоматически генерируется из SECRET_KEY через PBKDF2

## Как это работает

### Автоматическое шифрование

Когда вы используете модель `User`, все персональные данные **автоматически шифруются**:

```python
from app.models.user import User

# Создание пользователя
user = User(
    telegram_id=123456789,
    username="john_doe",          # ← Автоматически шифруется
    first_name="Иван",            # ← Автоматически шифруется
    preferred_name="Ваня",        # ← Автоматически шифруется
    city="Москва",                # ← Автоматически шифруется
    birth_year=1990,              # ← Автоматически шифруется
    chronic_conditions=["диабет"] # ← Автоматически шифруется
)

session.add(user)
session.commit()

# В базе данных сохраняются ЗАШИФРОВАННЫЕ значения!
```

### Автоматическое расшифрование

При чтении данных они **автоматически расшифровываются**:

```python
user = session.query(User).filter_by(telegram_id=123456789).first()

print(user.username)           # "john_doe" (расшифровано)
print(user.first_name)         # "Иван" (расшифровано)
print(user.city)               # "Москва" (расшифровано)
print(user.chronic_conditions) # ["диабет"] (расшифровано)

# Код работает так же, как и раньше!
```

## Какие данные шифруются

Все персональные данные согласно 152-ФЗ:

### Личная информация
- ✅ `username` - имя пользователя Telegram
- ✅ `first_name` - имя
- ✅ `last_name` - фамилия
- ✅ `preferred_name` - имя для обращения

### Локация
- ✅ `country` - страна
- ✅ `city` - город

### Физические данные
- ✅ `birth_year` - год рождения
- ✅ `height` - рост
- ✅ `current_weight` - текущий вес
- ✅ `target_weight` - целевой вес

### Здоровье (wellness данные)
- ✅ `chronic_conditions` - хронические заболевания
- ✅ `removed_organs` - удаленные органы
- ✅ `food_exclusions` - исключения из рациона

### Что НЕ шифруется
- ❌ `telegram_id` - нужен для поиска пользователей
- ❌ `gender` - enum, не содержит персональных данных
- ❌ `goal` - цель питания (не персональные данные)
- ❌ `diet_type` - тип диеты (не персональные данные)

## Миграция базы данных

После настройки ключей запустите миграции:

```bash
# 1. Добавить wellness поля
python migrate_add_wellness_fields.py

# 2. Зашифровать все персональные данные
python migrate_encrypt_personal_data.py
```

Миграция:
1. Добавит зашифрованные поля в таблицу `users`
2. Зашифрует все существующие данные
3. Опционально удалит старые незашифрованные поля

## Безопасность ключей

### ⚠️ КРИТИЧЕСКИ ВАЖНО:

1. **НЕ коммитьте .env в git!**
   ```bash
   # Убедитесь, что .env в .gitignore
   echo ".env" >> .gitignore
   ```

2. **Сделайте резервную копию ключей!**
   ```bash
   # Сохраните ключи в безопасном месте
   # Без ключей данные НЕВОЗМОЖНО восстановить!
   cp .env .env.backup
   # Храните .env.backup в БЕЗОПАСНОМ месте (не на сервере!)
   ```

3. **Используйте разные ключи для dev/prod**
   ```bash
   # Development
   .env.development

   # Production
   .env.production
   ```

4. **Ограничьте доступ к файлу .env**
   ```bash
   chmod 600 .env
   ```

## Технические детали

### Алгоритм шифрования
- **Fernet** (симметричное шифрование)
- Основан на **AES-128 в режиме CBC**
- Включает **HMAC SHA-256** для аутентификации
- Криптографически безопасен

### Генерация ключа из SECRET_KEY
Если `ENCRYPTION_KEY` не указан:
- Используется **PBKDF2** (Password-Based Key Derivation Function 2)
- Алгоритм: **SHA-256**
- Итераций: **100,000**
- Соль: `nutriai_encryption_salt_v1` (фиксированная)

```python
from cryptography.hazmat.primitives.kdf.pbkdf2 import PBKDF2
from cryptography.hazmat.primitives import hashes

kdf = PBKDF2(
    algorithm=hashes.SHA256(),
    length=32,
    salt=b'nutriai_encryption_salt_v1',
    iterations=100000,
)
key = kdf.derive(SECRET_KEY.encode())
```

### Формат хранения
- Зашифрованные данные хранятся как **TEXT** (base64)
- Совместимость с **PostgreSQL**
- Поддержка NULL значений

## Решение проблем

### Ошибка: "Invalid encryption key"
**Причина:** Ключ шифрования неверный или отсутствует

**Решение:**
```bash
# Сгенерируйте новый ключ
python3 generate_keys.py

# Добавьте SECRET_KEY в .env
```

### Ошибка: "Decryption error"
**Причина:** Данные зашифрованы другим ключом

**Решение:**
- Убедитесь, что используете тот же `SECRET_KEY` или `ENCRYPTION_KEY`
- Проверьте, что не изменили соль в коде

### Данные не расшифровываются
**Причина:** Возможно, данные еще не зашифрованы

**Решение:**
```bash
# Запустите миграцию для шифрования существующих данных
python migrate_encrypt_personal_data.py
```

## FAQ

**Q: Можно ли изменить ключ шифрования?**

A: Да, но потребуется расшифровать все данные старым ключом и зашифровать новым. Создайте миграцию для этого.

**Q: Влияет ли шифрование на производительность?**

A: Минимально. Шифрование/расшифрование происходит в памяти при чтении/записи. Для большинства приложений это незаметно.

**Q: Безопасно ли использовать один SECRET_KEY для всего?**

A: Да, при использовании PBKDF2 ключ достаточно безопасен. Но для максимальной безопасности рекомендуется использовать отдельный ENCRYPTION_KEY.

**Q: Что делать, если потерял ключи?**

A: К сожалению, зашифрованные данные будут потеряны навсегда. **ВСЕГДА делайте резервные копии ключей!**
