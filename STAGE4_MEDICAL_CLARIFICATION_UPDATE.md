# Этап 4 - Доработка: Уточнение медицинского состояния перед созданием рациона

## Проблема

При регистрации пользователи указывают хронические заболевания и удаленные органы. Однако эта информация может быть неактуальной к моменту создания плана питания:

1. **Хронические заболевания** могут находиться в разных стадиях:
   - Обострение - требуют строгих ограничений
   - Ремиссия - можно ослабить некоторые ограничения
   - Под контролем - стабильное состояние

2. **Острые состояния** могут возникнуть временно:
   - ОРВИ, простуда, грипп
   - Пищевое отравление
   - Проблемы с ЖКТ (диарея, запор)
   - Восстановление после болезни
   - Другие временные состояния

Эти факторы критически влияют на безопасность и эффективность рациона, поэтому **перед каждым созданием плана питания** бот должен уточнять актуальное медицинское состояние пользователя.

## Решение

### Архитектура решения

**Workflow создания плана питания:**
```
1. Пользователь выбирает период (день/неделя/месяц)
2. Бот уточняет время на готовку (если не задано)
3. Бот задает 3 вопроса о предпочтениях
4. **[НОВОЕ]** Бот проверяет есть ли хронические заболевания
5. **[НОВОЕ]** Если есть - уточняет текущее состояние
6. **[НОВОЕ]** Бот спрашивает про острые состояния
7. Бот генерирует план с учетом всех данных
```

### Технические изменения

#### 1. Новые состояния FSM (states.py)

```python
class MealPlanStates(IntEnum):
    WAITING_PERIOD = auto()
    ASKING_COOKING_TIME = auto()
    ASKING_PREFERENCES = auto()
    # Новые состояния:
    CHECKING_CHRONIC_CONDITIONS = auto()  # Уточнение хронических заболеваний

    GENERATING = auto()
    ASKING_FEEDBACK = auto()
    ASKING_CHANGES = auto()
```

#### 2. Новые тексты (texts.py)

Добавлены информативные тексты для медицинских уточнений:

- `MEDICAL_CHECK_INTRO` - введение в медицинское уточнение
- `get_chronic_conditions_check_text(conditions)` - динамический текст с вопросом о состоянии каждого хронического заболевания
- `ACUTE_CONDITIONS_CHECK` - вопрос о наличии острых состояний
- `MEDICAL_CHECK_COMPLETE` - подтверждение завершения медицинских уточнений

**Пример текста:**
```
📋 Хронические заболевания

При регистрации ты указал:
• Диабет
• Гастрит

⚠️ Важно: Некоторые хронические заболевания могут находиться в стадии ремиссии,
что влияет на диетические рекомендации.

Пожалуйста, укажи текущее состояние каждого заболевания:
• Обострение - требует строгих ограничений
• Ремиссия - можно ослабить некоторые ограничения
• Под контролем - стабильное состояние

Напиши текущее состояние для каждого заболевания.
Например: "Диабет - под контролем, Гастрит - ремиссия"
```

#### 3. Новые хандлеры (meal_plan.py)

**Добавлено 6 новых функций:**

1. `ask_acute_conditions(update, context, is_callback)`
   - Спрашивает про острые заболевания/состояния

2. `handle_chronic_conditions_response(update, context)`
   - Обрабатывает ответ о текущем состоянии хронических заболеваний
   - Сохраняет во временный контекст: `context.user_data["chronic_conditions_status"]`

3. `skip_chronic_conditions_check_callback(update, context)`
   - Обрабатывает пропуск проверки (кнопка "Без изменений")

4. `handle_acute_conditions_response(update, context)`
   - Обрабатывает ответ о наличии острых состояний
   - Сохраняет во временный контекст: `context.user_data["acute_conditions"]`

5. `skip_acute_conditions_callback(update, context)`
   - Обрабатывает пропуск (кнопка "Нет острых состояний")

6. `start_meal_plan_generation(update, context, is_callback)`
   - Начинает генерацию плана после всех уточнений
   - Показывает сообщение `MEDICAL_CHECK_COMPLETE`

**Обновлена функция:**
- `handle_preference_response()` - после 3-го вопроса о предпочтениях проверяет наличие хронических заболеваний и переходит к медицинским уточнениям

#### 4. Обновлен ConversationHandler (main.py)

Добавлены новые состояния в meal_plan_conversation:

```python
MealPlanStates.CHECKING_CHRONIC_CONDITIONS: [
    MessageHandler(filters.TEXT & ~filters.COMMAND, handle_chronic_conditions_response),
    CallbackQueryHandler(skip_chronic_conditions_check_callback, pattern="^skip_chronic_check$"),

MealPlanStates.CHECKING_ACUTE_CONDITIONS: [

    CallbackQueryHandler(skip_acute_conditions_callback, pattern="^skip_acute_check$"),
    CallbackQueryHandler(cancel_meal_plan, pattern="^main_menu$")
```


**Параметр `medical_context` содержит:**

**Обновлена функция `_build_meal_plan_prompt()`:**
- Добавлен параметр `medical_context`
- Если пользователь уточнил состояние хронических заболеваний - добавляется в промпт:
  ```

  ```

## Примеры использования

### Сценарий 1: Пользователь с хроническими заболеваниями

**При регистрации указал:** Диабет, Гастрит

**При создании плана:**
1. Бот спрашивает о текущем состоянии
2. Пользователь отвечает: "Диабет - под контролем, Гастрит - обострение"
3. Бот учитывает обострение гастрита и создает щадящий рацион

**Результат:**
- AI получает детальную информацию о текущем состоянии
- Рацион учитывает обострение гастрита (исключает острое, жареное, кислое)
- Диабет под контролем - стандартные ограничения

### Сценарий 2: Пользователь без хронических заболеваний

**При регистрации не указал заболевания**

**При создании плана:**
1. Бот пропускает вопрос о хронических заболеваниях
2. Сразу спрашивает про острые состояния
3. Пользователь отвечает: "Легкое отравление, диарея"

**Результат:**
- AI создает щадящий рацион с легкоусвояемыми продуктами
- Исключаются продукты, вызывающие брожение
- Увеличивается количество жидкости

### Сценарий 3: Пользователь здоров

**При регистрации не указал заболевания**

**При создании плана:**
1. Бот пропускает вопрос о хронических заболеваниях
2. Спрашивает про острые состояния
3. Пользователь нажимает "Нет острых состояний"

**Результат:**
- Создается стандартный план без дополнительных ограничений
- Учитываются только базовые параметры профиля

## Безопасность и этика

### Дисклеймеры

Перед медицинскими уточнениями показывается:
```
🏥 Уточнение медицинской информации

При регистрации ты указал медицинскую информацию.
Перед созданием рациона важно уточнить актуальное состояние здоровья.

Это помогает мне создать максимально безопасный и подходящий план питания.
```

### Ограничения

1. Бот **НЕ ставит диагнозы**
2. Бот **НЕ назначает лечение**
3. Бот **рекомендует обратиться к врачу** при серьезных состояниях
4. Все рекомендации касаются **только питания**

## Преимущества решения

### 1. Безопасность
- Рацион учитывает актуальное состояние здоровья
- Снижается риск ухудшения при обострении
- Острые состояния учитываются немедленно

### 2. Персонализация
- Рацион адаптируется под текущее состояние
- Учитываются временные ограничения
- Более гибкий подход к хроническим заболеваниям

### 3. UX
- Пользователь чувствует заботу
- Не нужно вручную редактировать профиль
- Быстрое уточнение перед каждым планом

### 4. Юридическая защита
- Бот активно собирает актуальную информацию
- Пользователь подтверждает свое состояние
- Снижается риск негативных последствий

## Технические детали

### Данные хранятся временно
Уточненные медицинские данные **НЕ сохраняются в базу данных**, они:
- Хранятся в `context.user_data` только на время создания плана
- Передаются в `MealPlanService.generate_meal_plan()` как `medical_context`
- Включаются в AI промпт для генерации
- Удаляются после завершения ConversationHandler

### Почему не сохраняем в БД?
1. **Актуальность:** Острые состояния временны, сохранение бессмысленно
2. **Простота:** Не нужно создавать дополнительные таблицы
3. **Гибкость:** Пользователь каждый раз может указать новую информацию

### Постоянные vs Временные данные

**Постоянные (хранятся в `users` таблице):**
- `chronic_conditions` - список хронических заболеваний
- `removed_organs` - список удаленных органов
- `medical_restrictions` - AI-сгенерированные ограничения

**Временные (context.user_data):**
- `chronic_conditions_status` - текущее состояние хронических заболеваний
- `acute_conditions` - текущие острые состояния

## Будущие улучшения

### Возможные доработки:
1. **Сохранение истории острых состояний** - для анализа паттернов
2. **Умные подсказки** - если пользователь часто указывает одно и то же острое состояние
3. **Интеграция с медицинскими анализами** - автоматическое предложение уточнить состояние при наличии плохих показателей
4. **Напоминания о проверке состояния** - если план создается через большой промежуток времени

## Заключение

Доработка **"Уточнение медицинского состояния"** критически важна для безопасности пользователей и качества рекомендаций.

Система учитывает:
- ✅ Текущее состояние хронических заболеваний (обострение/ремиссия)
- ✅ Временные острые состояния (ОРВИ, отравление, и т.д.)
- ✅ Актуальность данных на момент создания плана
- ✅ Гибкость в зависимости от состояния

Это делает NutriAI более безопасным, персонализированным и ответственным AI-ассистентом по питанию.
